## Project Overview

This is a **Betting/Voting Application** called "Stakes" — a satirical platform that enables users to create bets, organize them by stake/project, and vote on outcomes in real-time. The application is built with FastAPI, persists data to DynamoDB, and uses HTMX for interactive frontend updates without full page reloads.

**Key Terminology:**
- **Stake/Project:** A named betting group (e.g., "Sports Bets 2026"). Projects contain multiple bets and are created with unique IDs.
- **Bet/Event:** Individual predictions within a stake (e.g., "Will the Knicks win the championship?").
- **Vote:** A yes/no vote on a bet's outcome.

## Tech Stack

- **Backend:** FastAPI 0.129.2 + Python 3.10+
- **Frontend:** HTML templates (generated by Python), Tailwind CSS (CDN), HTMX (CDN)
- **Data Storage:** AWS DynamoDB (two tables: `votes_table_name` and `bets_table_name`)
- **Deployment:** AWS Lambda via Mangum (ASGI adapter)
- **Configuration:** Environment variables via `.env` file

## Architecture

### Data Layer (DynamoDB)

Two DynamoDB tables:

1. **Bets Table** (`bets_table_name`):
   - `event_id` (String): Unique timestamp when bet was created
   - `project` (String): Stake/project name
   - `title` (String): Bet description
   - `created_at` (String): ISO timestamp
   - `status` (String): Optional, e.g., "closed"
   - Index: `ProjectIndex` (queries by project)

2. **Votes Table** (`votes_table_name`):
   - `timestamp` (String): Vote timestamp (partition key)
   - `event_id` (String): Links to bet
   - `vote` (String): "yes" or "no"

### Frontend Pattern

All responses are **HTML-first** — no JSON API (except `/votes/{event_id}`). HTMX is used for dynamic voting:

1. User clicks a vote button
2. HTMX POSTs to `/event/{encoded_event_id}?vote=yes|no`
3. Server updates vote counts in DynamoDB
4. Server returns rendered event card HTML
5. HTMX swaps the card in-place (no page reload)

### Encoding Strategy

Event IDs are **base64url-encoded** in HTML:
- Event ID in DB: ISO timestamp string (e.g., `2026-03-30T20:33:45.123456+00:00`)
- Encoded in HTML: `base64url(event_id)` for safe use in selectors/URLs
- Functions: `encode_event_id()` and `decode_event_id()` in `main.py`

## API Routes

### Public Endpoints

- `GET /` — Home page (all bets grouped by stake, forms to create bets/projects)
- `GET /{project}` — View all bets in a stake
- `GET /about` — About page (satirical, static HTML)
- `POST /add-bet` — Create a new bet (form: `project`, `title`)
- `POST /create-project` — Create a new stake (form: `project_name`), returns unique stake ID
- `POST /go-to-project` — Redirect to stake page (form: `project`)
- `POST /event/{item}?vote=yes|no` — Vote on a bet (HTMX), returns updated card HTML
- `GET /votes/{event_id}` — JSON list of votes for a bet (query/API endpoint)

### Restricted Endpoints (IP-gated via `allowed_clear_ips`)

- `GET /clear` — Delete all votes from the votes table

## Key Functions

### DynamoDB Operations

- `save_vote_to_dynamodb(timestamp, event_id, vote)` — Insert vote record
- `get_vote_counts_from_dynamodb(event_id)` — Return `{"yes": count, "no": count}`
- `save_bet_to_dynamodb(event_id, project, title)` — Insert bet
- `get_all_bets_from_dynamodb()` — Scan all bets
- `get_bets_by_project_from_dynamodb(project)` — Query bets by project
- `get_bet_by_event_id(event_id)` — Scan and return single bet

### Utilities

- `encode_event_id(event_id)` — Base64url-encode event ID
- `decode_event_id(encoded_id)` — Base64url-decode event ID
- `generate_project_id()` — Generate random 8-char stake ID
- `get_timestamp()` — Return ISO timestamp with UTC timezone

### Template Generators (in `templates/pages.py` and `event/event.py`)

- `generate_event_card(item)` — Render single bet card with vote buttons
- `events(grouped_items)` — Render all cards (supports dict grouped by stake or flat list)
- `generate_bar_chart(votes)` — Render yes/no vote distribution bar
- `header(app_name, slogan)` — Render page header with navigation
- `about(app_name, slogan)` — Render about page

## Frontend Interaction

**HTMX Attributes Used:**
- `hx-post="/event/{id}?vote=yes"` — POST on button click
- `hx-target="#event-{id}"` — Target element to swap
- `hx-swap="outerHTML"` — Replace entire element

**Styling:**
- Tailwind CSS (CDN from cdn.jsdelivr.net)
- Dark theme: `bg-slate-900` (body), `bg-slate-700` (cards)
- Buttons: Green for "Yes", Red for "No", Gray if bet is closed
- Responsive grid: 1 col (mobile) → 2 cols (sm) → 3 cols (md) → 4 cols (lg)

## Settings & Configuration

The `Settings` class (Pydantic-based) loads from environment:
- Must have `.env` in the working directory or set env vars before import
- All settings are strings (accessed via `os.getenv()` in class definition)
- If an env var is missing, it defaults to `None` (except `allowed_clear_ips` which defaults to `'127.0.0.1,localhost'`)

## IP-Based Access Control

The `/clear` endpoint restricts to IPs in `allowed_clear_ips`:
- Check: `client_ip = request.client.host`
- Allow list: parse comma-separated string from settings
- Used to prevent accidental data wipes

## Common Gotchas

1. **Event IDs are timestamps, not UUIDs** — Multiple bets created at the same millisecond could collide; currently no deduplication.
2. **No bet deletion** — Bets are persisted forever; `/clear` only clears votes, not bets.
3. **Project names are case-sensitive** — `/Stakes` and `/stakes` are different projects.
4. **Pagination in DynamoDB** — `scan()` operations don't paginate by default; high vote counts may need explicit pagination handling.
5. **Mangum lifespan disabled** — `Mangum(app, lifespan="off")` means FastAPI lifespan events won't run; avoid startup/shutdown hooks.
